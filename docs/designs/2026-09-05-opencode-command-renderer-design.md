# Design: Multi-Target Command Renderer

## Goal

Render every `command-support/gm/*.yaml` definition for Claude Code and OpenCode from one source of truth, with a first-class OpenCode installer that prevents cross-client drift.

## Approved Approach

Implement the renderer in `godmode-core` and expose target-aware generation and installation through the `godmode` CLI.

## Context Map

### Files to Modify

| File                                     | Purpose                      | Change                                                                       |
| ---------------------------------------- | ---------------------------- | ---------------------------------------------------------------------------- |
| `crates/godmode-core/src/command.rs`     | Command domain logic         | Add YAML loading, target rendering, reference rewriting, and file projection |
| `crates/godmode-core/src/lib.rs`         | Core module exports          | Export the command module                                                    |
| `crates/godmode-cli/src/main.rs`         | CLI entry point              | Add `command generate` and `command install-opencode` actions                |
| `command-support/gm/generate.nu`         | Legacy generator entry point | Delegate to the Rust renderer instead of owning rendering logic              |
| `command-support/gm/README.md`           | Command-source documentation | Document multi-target generation and OpenCode installation                   |
| `README.md`                              | User documentation           | Document the new CLI commands                                                |
| `tests/conformance/src/lib.rs`           | Conformance registration     | Register command renderer checks if a dedicated module is added              |
| `tests/conformance/src/command_tests.rs` | Cross-client contracts       | Verify source coverage and rendered command naming                           |

### Dependencies

| File                                      | Relationship                                           |
| ----------------------------------------- | ------------------------------------------------------ |
| `command-support/gm/*.yaml`               | Canonical command definitions consumed by the renderer |
| `command-support/gm/templates/*.md`       | Optional prompt templates resolved during rendering    |
| `commands/gm-*.md`                        | Tracked Claude output regenerated by the renderer      |
| `$HOME/.config/opencode/commands/gm-*.md` | OpenCode installation destination                      |
| `crates/godmode-core/src/agent.rs`        | Existing render/install pattern for OpenCode assets    |

### Reference Patterns

| File                               | Pattern                                                              |
| ---------------------------------- | -------------------------------------------------------------------- |
| `crates/godmode-core/src/agent.rs` | Load declarative YAML, render Markdown, support dry-run installation |
| `crates/godmode-cli/src/main.rs`   | `agent install-opencode` argument and default-path handling          |
| `/dev/opavs/src/plugin.rs`         | OpenCode command frontmatter: description plus `subtask: false`      |

### Risk

- The renderer changes generated Claude files; output compatibility must be snapshot-tested.
- OpenCode command references use `/gm-name`, while Claude references use `/gm:name`.
- Installation writes outside the repository by default and therefore requires an explicit command.
- No serialization migration or external dependency is required.

## Crate Ownership

- **Owner crate**: `godmode-core` — parsing and rendering are reusable domain operations independent of CLI argument handling.
- **Affected crate**: `godmode-cli` — exposes the renderer and installer as thin commands.
- **Conformance crate**: `godmode-conformance` — verifies every canonical source renders for both targets.

## Public API

### Types

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum CommandTarget {
    Claude,
    OpenCode,
}

#[derive(Debug, Clone, serde::Deserialize, PartialEq, Eq)]
pub struct CommandDefinition {
    pub name: String,
    pub description: Option<String>,
    pub template: Option<String>,
    pub prompt: String,
    pub allowed_tools: Vec<String>,
    pub max_turns: Option<u32>,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct RenderedCommand {
    pub file_name: String,
    pub content: String,
}
```

### Functions

```rust
pub fn load_command_definitions(source_dir: &std::path::Path)
    -> anyhow::Result<Vec<CommandDefinition>>;

pub fn render_commands(
    definitions: &[CommandDefinition],
    target: CommandTarget,
    template_dir: &std::path::Path,
) -> anyhow::Result<Vec<RenderedCommand>>;

pub fn write_rendered_commands(
    commands: &[RenderedCommand],
    output_dir: &std::path::Path,
    dry_run: bool,
) -> anyhow::Result<Vec<std::path::PathBuf>>;

pub fn check_rendered_commands(
    commands: &[RenderedCommand],
    output_dir: &std::path::Path,
) -> anyhow::Result<()>;
```

No new trait is needed: filesystem access is already the established adapter boundary for agent installation, and adding a one-implementation port would not improve the current requirement.

## CLI Contract

```text
godmode command generate --target <claude|opencode> [--source-dir PATH] [--output-dir PATH] [--check]
godmode command install-opencode [--source-dir PATH] [--output-dir PATH] [--dry-run]
```

- `generate --target claude` defaults to repository `command-support/gm/` and `commands/`.
- `generate --target opencode` requires `--output-dir` to avoid an implicit external write.
- `install-opencode` defaults to `$HOME/.config/opencode/commands/` and is the only command that writes there implicitly.
- `--check` compares expected content without writing and fails on missing, stale, or unexpected managed `gm-*.md` files.
- `--dry-run` prints every destination without creating directories or files.

## Rendering Rules

1. Load and sort every top-level YAML definition by filename.
2. Resolve optional templates from `command-support/gm/templates/`.
3. Derive a description from the first non-empty prompt line when absent.
4. Render Claude frontmatter with `description` and `allowed-tools`.
5. Render OpenCode frontmatter with `description` and `subtask: false`.
6. Rewrite canonical `/gm:<name>` references to `/gm-<name>` only for OpenCode output.
7. Preserve `$ARGUMENTS` literally in both targets.
8. Write atomically enough for each individual command: render fully before replacing its destination.

## Data Flow

1. Source: YAML definitions and optional Markdown templates are read from `command-support/gm/`.
2. Transform: definitions are validated, rendered for a target, and command references are normalized for that target.
3. Sink: generated Markdown is written to a caller-selected directory or the explicit OpenCode installation directory.

## Hexagonal Boundaries

- **Domain**: command definition validation and target-specific string rendering in `godmode-core::command`.
- **Filesystem adapter**: load, compare, and write functions in the same focused module, matching the existing agent installer convention.
- **CLI adapter**: Clap target parsing and default path resolution in `godmode-cli`.

## Validation

- Unit tests cover YAML defaults, deterministic ordering, template resolution, both frontmatter formats, command-reference rewriting, dry-run behavior, and stale checks.
- CLI tests cover default Claude generation, required OpenCode output selection, and OpenCode installer dry-run.
- Conformance verifies one rendered file per YAML source for both targets and checks the five lifecycle commands form the correct target-specific chain.

## Out of Scope

- Installing commands for editors other than Claude Code and OpenCode.
- Assigning dedicated OpenCode agents to each command.
- Deleting unrelated user-authored OpenCode commands.
- Changing command prompt semantics beyond target-specific invocation syntax.

## Risk

- [x] Breaking API changes: no; all public APIs are additive.
- [x] New external dependency: no.
- [x] Feature flag required: no.
- [x] External write: yes, only through explicit `command install-opencode`.
