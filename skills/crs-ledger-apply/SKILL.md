# crs-ledger-apply

Merge `crs-ledger-diff`'s proposed entries into the installed rule-ledger
YAML, then regenerate the Markdown view from that YAML plus live
`crs-stats.json` numbers. This is the merge/render half of the coursers
rule-ledger pair; `crs-ledger-diff` is the discover/propose half.

## When to Use

- After `crs-ledger-diff` has written `.ctx/coursers/rule-ledger-proposed.yaml`
- Asked to "apply the ledger proposal" or "regenerate the rule ledger"
- To refresh `rule-ledger.md`'s numbers even with no new rows (e.g. after a
  rule has tripped a few more times)

## Steps

1. Read `.ctx/coursers/rule-ledger-proposed.yaml`. If it is missing or `{}`,
   report "nothing to merge" and continue to step 3 anyway — the Markdown
   view still needs regenerating since `crs-stats.json` counts may have
   changed since the last render.
2. Read `.ctx/coursers/rule-ledger.yaml` (empty mapping if missing). For
   each key in the proposed file, add it to the ledger **only if that key
   is not already present**. Never overwrite an existing entry — a human
   may have already filled in its prose. Write the merged result back to
   `.ctx/coursers/rule-ledger.yaml`.
3. Read `.ctx/coursers/crs-stats.json` (`blocks` = counts, `last_seen` =
   epoch floats per rule ID). Regenerate `.ctx/coursers/rule-ledger.md`:
   - Header: `<!-- generated by crs-ledger-apply — do not hand-edit; edit
rule-ledger.yaml instead -->`
   - One table per `category` found in the merged YAML, columns: Rule ID |
     Occurrences | Last seen | Pattern | Prevention | Notes
   - `Occurrences`/`Last seen` always come from `crs-stats.json` at render
     time — never read or written from the YAML. A rule with no entry in
     `crs-stats.json` yet (never triggered) renders as `0` / `never`.

## Contract

- **Input**: `.ctx/coursers/rule-ledger-proposed.yaml` (from
  `crs-ledger-diff`), `.ctx/coursers/rule-ledger.yaml`,
  `.ctx/coursers/crs-stats.json`
- **Output**: updated `.ctx/coursers/rule-ledger.yaml` (only if new rows
  were merged) and an always-regenerated `.ctx/coursers/rule-ledger.md`
- Never deletes entries flagged as orphaned by `crs-ledger-diff` — this step
  only ever writes what diff proposed; orphan pruning is a manual edit to
  `rule-ledger.yaml`.
- Never touches `~/.config/coursers/course-correct-rules.json`,
  `.ctx/coursers/crs-stats.json` (read-only here), or anything under
  `.ctx/memory-bank/`.
